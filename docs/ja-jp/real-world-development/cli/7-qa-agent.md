`quality-checks` スキルを使って自動チェックを実行し、Playwright MCP でブラウザー上のフィルタリングを確認しました。次は、明確な QA プロセスを定めたカスタムエージェントに、これらの機能をまとめます。

このレッスンでは、次のことを行います。

- カスタムエージェントがインストラクション、スキル、MCP ツールをどう使うかを確認します。
- 再利用可能な品質保証プロファイルを作成し、内容を確認します。
- QA エージェントを選択し、フィルタリングの issue に照らして結果を確認します。

## シナリオ

Tailspin Toys は、プルリクエスト（PR）を作成する前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザー上の動作を一貫して確認したいと考えています。カスタムエージェントを使うと、QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する、特定の役割に特化した Copilot です。プロファイルでは、エージェントの目的、インストラクション、利用可能なツールを指定します。このワークショップでは `.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリのインストラクションにはチームの標準を記述します。`quality-checks` スキルは繰り返し利用するチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、要件を評価して結果を報告するために Copilot がそれらの機能をどう使うかを指示します。これらを置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用可能な QA プロファイルを Copilot に作成してもらいます。プロファイルには、QA で行うチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、新しいカスタムエージェントの作成を依頼します。

   ```plaintext
   `.github/agents/qa.agent.md` に QA という名前のカスタムエージェントを作成してください。issue と合意した要件に照らして機能を確認し、リポジトリのインストラクションに従い、`quality-checks` スキルを実行し、Playwright MCP を使って動作を検証してください。テストカバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を示しながら pass、fail、blocked のいずれかで報告させてください。実装コードを変更する前に必ず確認し、変更をコミットしたりプルリクエストを作成したりしないようにしてください。

   まずはプロファイルだけを作成してください。内容は後でレビューします。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA の手順と制約を反映しているか確認します。こうすることで、検証だけを依頼したのに、プロファイルの不足や範囲の広さが原因でエージェントが機能を変更する事態を防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は省略可能ですが、指定すると表示名が分かりやすくなります。
3. プロファイルのインストラクションを読み、QA が要件を起点とし、リポジトリのインストラクションに従い、`quality-checks` スキルを実行し、Playwright MCP を使うことを確認します。
4. QA が根拠を示して結果を報告し、実装コードを変更する前に確認を求め、変更をコミットしたり PR を作成したりしないことを確認します。
5. いずれかが抜けていたら、続行する前に既定のエージェントに修正を依頼します。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成したら、フィルタリングの会話を再開し、QA を選択します。これでエージェントは、既に会話に含まれている issue と計画時の決定事項を使えます。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成直後のエージェントは、利用可能なエージェントの一覧に表示されない場合があります。次のコマンドで有効化できます。

2. 次のプロンプトで、QA エージェントに機能のレビューを依頼します。

   ```plaintext
   issue と計画時の決定事項に照らして、フィルタリング機能をレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントの作業が始まります。
4. 完了したら、出力されたレポートを読みます。
