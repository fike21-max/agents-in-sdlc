フィルター機能の実装、指示の更新、スキルの更新、品質保証（QA）プロファイル、テストを 1 つのブランチに保存しました。これらをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト（PR）は自分でマージしましたが、今回は **Agent Merge** にプロセスを管理させます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントをいくつかの PR に分けます。ワークショップを簡潔に進めるため、フィルター機能と品質に関する作業全体を 1 つのセッションとブランチで続け、この PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge と、マージのライフサイクルを自動化する仕組みを確認します。
- 機能の PR 全体と検証の証拠を調べます。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローを通じて、Copilot で機能を計画、実装、検証しました。Tailspin Toys では、マージの承認を開発者の管理下に置きながら、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み取り、マージを妨げている問題（失敗した継続的インテグレーション（CI）チェックの修正、レビューコメントへの対応、必要に応じたリベースなど）を解決し、GitHub が許可した時点でマージします。バックグラウンドで動作し、アプリを再起動しても継続します。プルリクエストがマージされると自動的に無効になります。

ここまでは、自分で **Merge pull request** を選択していました。Agent Merge にその役割を任せることもできますが、コードの編集やマージには明示的な許可が必要です。マージ権限を与える前に、許可される操作と作業内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したので、Agent Merge に PR のプロセスを管理させましょう。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンの表示が **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウン項目を選ぶだけでは開始されません。

Agent Merge のプロセスが始まると、次の処理を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- issue からセッションを開始した場合は、説明の本文で関連する issue を参照します。
- リベースを行うか、ターゲットブランチとのマージ競合に対処します。
- CI を監視し、すべてのチェックが成功することを確認します。
- ほかの開発者や Copilot のコードレビューからフィードバックがないか PR を監視し、コメントを解決するために変更します。
- すべての処理が成功した後、PR を自動的にマージするよう設定できます。

すべてのチェックが成功した後に Agent Merge が PR もマージするよう設定しましょう。

5. マージ権限を許可する前に、PR の差分と検証の証拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. エージェントにマージを明示的に依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進捗を確認し、報告されたブロッカーを解決します。次に進む前に、PR の状態が **Merged** であることを確認してください。マージ権限を有効にしたことや、エージェントが実行中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行する前に、これらのブロッカーを解決してください。
