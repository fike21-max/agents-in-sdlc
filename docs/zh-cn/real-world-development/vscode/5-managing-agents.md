让 GitHub Copilot 进入代理模式后，它会自主探索代码库、提出更改建议、编辑文件并运行命令。由于这些工作会实时在你的计算机上进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以在聊天中查看每项差异、接受或拒绝单项更改，还可以通过后续提示引导对话来完善或扩展工作，无需离开编辑器。

在本练习中，你将：

- 实时监控可访问性代理的工作；
- 检查并接受建议的文件编辑；
- 在会话中途引导代理，在高对比度模式之外再添加浅色模式切换开关。

## 场景

你在[练习 4][previous-lesson]中使用的可访问性自定义代理正在实现高对比度模式。工作尚未完成时，设计团队又提出了一个需求：也为觉得默认主题太暗的用户添加浅色模式切换开关。无需从头开始新对话，你可以引导现有会话继续扩展功能。

## 监控 Copilot 的进度

Copilot Chat 视图会显示代理执行的每一步操作，包括探索的文件、运行的命令和提出的编辑建议。每项文件编辑都会以内联方式显示在聊天中，并提供差异以及 **Keep** / **Undo** 控件。

1. 返回练习 4 使用的 Copilot Chat 视图。
2. 代理工作期间，滚动聊天记录，观察每次工具调用。你会看到文件读取、文件编辑，以及它请求运行的终端命令。
3. 代理提出文件编辑建议时，差异会以内联方式显示：
    - 选择 **Keep** 接受更改。
    - 选择 **Undo** 撤销更改，让代理重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看代理在此会话中修改的全部文件。

> [!NOTE]
> 如果工具调用需要权限（例如运行终端命令），代理会暂停并显示 **Allow** 提示。只批准你认为可以接受的命令。

5. 等待代理完成高对比度模式的实现。完成后，你会看到一条总结所做更改的最终消息。

## 引导代理添加浅色模式

高对比度模式就绪后，你将在同一对话中继续添加浅色模式切换开关。由于继续使用同一聊天会话，代理会保留之前工作的所有上下文，包括修改过的组件、采用的样式方案以及设置的本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在请在高对比度切换开关旁添加浅色模式切换开关。浅色模式应采用相同的模式：通过本地存储保留设置，并且可以从 UI 的同一区域访问。用户应能够独立启用高对比度模式和浅色模式。
    ```

2. 代理会从之前的工作继续，探索已有更改，并提出添加浅色模式的方案。
3. 像检查高对比度模式一样，逐项检查新编辑。对每项差异选择 **Keep** 或 **Undo**。
4. 如果代理采用了你不希望看到的方案，例如试图以你不喜欢的方式重构切换开关 UI，可以选择聊天输入框旁边的 **Stop** 按钮停止代理，然后发送一条补充说明。

> [!TIP]
> 与从头开始相比，引导正在进行的会话更快。可以使用后续提示提出调整要求（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（“不要添加第三个切换开关，请将浅色模式整合到现有设置面板中”），或扩展范围（“也为两个切换开关添加键盘快捷键”）。

## 检查工作集

提交更改之前，快速检查代理修改的全部内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 检查所有已更改文件。你应该会看到 Astro 组件、样式和相关测试都有更新。
3. 打开几个已更改文件并检查差异。确认其中体现了自定义代理遵循的可访问性模式，包括 ARIA 属性、键盘导航、语义化 HTML 和通过本地存储持久化设置。
4. 确认无误后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 代理模式监控并引导了正在进行的会话：查看每项文件编辑、接受或拒绝更改，并在保留上下文的同时发送后续提示来扩展工作。

本课介绍了以下内容：

- 实时监控代理的工作；
- 接受或拒绝单项文件编辑；
- 在会话进行中使用后续提示引导代理。

在[下一课][next-lesson]中，你将把可访问性相关更改作为拉取请求发布，并检查本实验中本地自定义代理生成的更改。
